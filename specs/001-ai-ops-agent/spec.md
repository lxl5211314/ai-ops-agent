# Feature Specification: 智能运维助手「小龙」（AI Ops Agent）

**Feature Branch**: `001-ai-ops-agent`

**Created**: 2026-09-25

**Status**: Draft

**Input**: User description: "我现在想做一个智能运维agent，它有一个运维助手小龙的助手，用户可以对话询问运维相关知识并分析给出原因和解决方案，同时用户能在前端界面上创建文件夹，并上传项目源码或者在页面端输入项目源代码路径，给出路径后，用户可以指出bug，agent会自动定位分析BUG并解析和给出Patch补丁，第一版先简单点，把核心功能先跑通即可"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运维知识对话问答（Priority: P1）

用户打开界面，与运维助手「小龙」进行对话，提出运维相关问题（如"服务响应变慢怎么排查"、"磁盘满了怎么办"）。小龙分析问题后，给出可能原因与对应的解决方案，以对话形式呈现。

**Why this priority**: 对话问答是整个产品的入口与核心价值载体，独立即可交付可用价值，是 MVP 的最小闭环。

**Independent Test**: 在界面输入一个运维问题，无需配置任何项目，即可在数秒内收到包含"原因分析 + 解决方案"的回复。

**Acceptance Scenarios**:

1. **Given** 用户处于对话界面且无任何项目，**When** 用户输入一个运维问题并发送，**Then** 系统在合理时间内返回包含原因分析和解决方案的回复
2. **Given** 用户连续追问同一话题的细节，**When** 用户发送后续消息，**Then** 回复与上文语境保持连贯
3. **Given** 用户提出的问题超出运维知识范围或描述含糊，**When** 系统处理该问题，**Then** 系统给出澄清性提问或说明无法回答，而不是编造答案
4. **Given** 对话进行中，**When** 用户清空历史，**Then** 界面回到初始状态，可重新开始对话

---

### User Story 2 - 项目源码接入（Priority: P2）

用户在前端界面上创建文件夹，并向其中上传项目源码文件；或者直接在页面上输入本地项目源代码的路径。系统确认该源码已就绪，可供后续 Bug 分析使用。

**Why this priority**: 源码接入是 Bug 定位分析的前置条件，但不依赖 Bug 分析即可独立验证（能看到文件、目录结构即算成功）。

**Independent Test**: 创建文件夹并上传一个示例项目（或填写一个有效路径），系统展示已接入的项目内容清单。

**Acceptance Scenarios**:

1. **Given** 用户在界面中，**When** 用户创建一个新文件夹，**Then** 文件夹出现在界面文件列表中且可被选中
2. **Given** 已创建文件夹，**When** 用户向该文件夹上传源码文件（可多选，含压缩包），**Then** 系统接收并展示上传后的文件/目录结构
3. **Given** 用户不上传文件，**When** 用户在页面输入本地项目源代码路径并提交，**Then** 系统校验路径有效性并回显该路径下可识别的项目结构概览
4. **Given** 提交的路径不存在或不可读，**When** 系统校验，**Then** 系统给出明确错误提示，且不改变现有已接入项目状态
5. **Given** 已接入项目，**When** 用户查看，**Then** 能看到项目名称、接入方式（上传/路径）与接入时间

---

### User Story 3 - Bug 自动定位、分析与补丁生成（Priority: P3）

用户在已接入的项目基础上指出 Bug（用自然语言描述现象，或粘贴报错信息），小龙自动定位相关代码位置，分析根因，并给出解析说明与可下载/可复制的 Patch 补丁。

**Why this priority**: 这是产品的差异化核心价值，但依赖 Story 2 的源码接入，因此在核心对话与源码接入跑通后再实现。

**Independent Test**: 接入一个含已知缺陷的示例项目，描述缺陷现象，系统返回定位到的文件位置、根因解析与一份可应用的补丁。

**Acceptance Scenarios**:

1. **Given** 已接入一个项目，**When** 用户描述一个 Bug 现象并提交，**Then** 系统返回至少一个具体代码位置（文件与相关片段）
2. **Given** 系统已完成定位，**When** 结果返回给用户，**Then** 结果同时包含：定位位置、原因解析、修复建议，以及一份 Patch 补丁文本
3. **Given** 系统生成的 Patch，**When** 用户将该 Patch 应用到原项目副本上，**Then** Patch 可被成功应用且不产生冲突（在受支持的项目规模内）
4. **Given** 系统无法定位到有效原因，**When** 分析失败，**Then** 系统明确说明未能定位并给出需要用户补充的信息（如更多日志、复现步骤），不输出臆造的补丁
5. **Given** 用户描述的 Bug 与已接入项目无关或项目为空，**When** 系统处理，**Then** 系统给出提示并引导用户先接入正确源码

---

### Edge Cases

- 路径指向超大型仓库（文件数极多）时，系统应给出规模提示并在合理时间内完成接入或明确拒绝并说明原因
- 上传的压缩包损坏、或包含不支持的二进制文件时，系统跳过不可解析内容并汇总告知用户
- 用户在 Bug 分析进行中离开页面或重复点击提交，系统不应产生重复分析任务或状态错乱
- 同一项目被多次接入（重复路径/重复上传）时，系统应提示已存在而非静默覆盖
- 用户提出的运维问题包含敏感信息（如密码、密钥）时，界面给出不记录/脱敏提示
- Patch 应用后原文件发生变化（用户在分析期间编辑了源码）时，Patch 标记为可能失效并提示用户
- 网络或模型服务不可用时，对话与分析均应返回可读的错误提示，界面不白屏、不无限加载

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个对话界面，用户可与运维助手「小龙」进行多轮问答
- **FR-002**: 系统 MUST 针对用户提出的运维问题给出"原因分析"与"解决方案"两部分内容
- **FR-003**: 系统 MUST 保持单个会话内的上下文连贯，使追问能基于前文理解
- **FR-004**: 系统 MUST 允许用户在界面上创建文件夹
- **FR-005**: 系统 MUST 允许用户将项目源码文件上传至所选文件夹，并展示上传后的结构
- **FR-006**: 系统 MUST 允许用户在页面输入本地项目源代码路径以接入源码，并对路径有效性做校验与反馈
- **FR-007**: 系统 MUST 展示已接入项目的概览（名称、接入方式、接入时间、结构摘要）
- **FR-008**: 用户 MUST 能基于已接入项目，用自然语言（可附报错文本）描述一个 Bug 并提交分析
- **FR-009**: 系统 MUST 自动定位 Bug 相关代码位置，并以文件路径 + 关键片段的形式呈现
- **FR-010**: 系统 MUST 输出对该 Bug 的根因解析（为什么会产生该现象）
- **FR-011**: 系统 MUST 生成可复制/可下载的 Patch 补丁，用于修复该 Bug
- **FR-012**: 系统 MUST 在无法定位或无法回答时明确告知用户并说明所需补充信息，不得编造结论
- **FR-013**: 系统 MUST 对无效路径、空项目、超大仓库、损坏文件等情况给出明确、可读的错误提示
- **FR-014**: 系统 MUST 在分析进行中向用户提供进度/加载状态，避免无反馈等待
- **FR-015**: 系统 MUST 记录每个会话的对话历史，直到用户清空或会话结束

### Key Entities

- **会话（Conversation）**: 用户与小龙的一次对话，包含消息历史、创建时间
- **消息（Message）**: 会话中的单条内容，区分用户/助手角色，含时间戳
- **项目（Project）**: 用户接入的源码集合，含名称、接入方式（上传/路径）、接入时间
- **文件夹（Folder）**: 用户在界面创建的容器，用于归集上传的源码文件
- **源码文件（Source File）**: 上传的文件或路径接入项目中的文件，含相对路径与内容
- **Bug 分析任务（Bug Analysis）**: 针对某项目某次 Bug 描述产生的分析，含 Bug 描述、定位结果、根因解析、Patch 内容、状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开界面到收到首条运维问答回复，平均不超过 30 秒
- **SC-002**: 90% 的常见运维问题（故障排查、配置、性能类）能获得包含原因与解决方案的完整回复
- **SC-003**: 用户从创建文件夹到完成源码接入，操作可在 2 分钟内完成（不含超大仓库上传耗时）
- **SC-004**: 对预置的已知缺陷示例项目，系统在 80% 的用例上能定位到正确的文件位置
- **SC-005**: 生成的 Patch 在示例项目上可直接应用成功率达 80%，无需用户手工改写
- **SC-006**: 无效路径、空项目、分析失败等异常场景 100% 返回明确提示，不出现无响应或界面卡死
- **SC-007**: 80% 的试用用户能在无人工指导的情况下独立完成"提问 → 接入项目 → 提交 Bug → 获得补丁"的完整流程

## Assumptions

- 第一版为单用户/无权限体系的本地或内网工具，不实现登录、注册与多租户
- 对话问答的知识来源依赖所接入的智能模型能力，第一版不自建运维知识库
- 源码接入支持常见文本代码文件与压缩包；不支持的二进制/超大文件会被跳过并提示
- Patch 以用户可直接复制应用的形式提供，第一版只保证在未被修改的原代码副本上应用成功
- 单次 Bug 分析针对一个项目中的一个 Bug 描述；批量 Bug、自动执行修复不在第一版范围
- 界面语言为中文，第一版只需支持桌面端浏览器
- 数据（会话、项目、分析结果）在第一版中仅需在服务运行期间可用，无需保证长期归档
- 分析失败或模型不可用时降级为错误提示，不提供离线兜底能力
